# CoreWatch — 통신망 장비 이상 탐지 및 원인 분석 AI 에이전트

CoreWatch는 이동통신망의 핵심 장비 데이터를 지켜보다가 평소와 다른 움직임(이상)을 찾아내고,
그 원인을 추정할 수 있는 근거를 모아 운영자에게 분석 리포트로 알려 주는 AI 에이전트입니다.

## 어떤 문제를 푸나요?

- 휴대폰이 통신망에 접속하고, 위치를 알리고, 전화·문자를 받을 수 있게 관리하는 장비를 **MME**라고 합니다.
- 운영자는 이 장비들이 처리한 일의 **시도 건수와 성공률(성능 지표)** 을 매시간 지켜봅니다.
- 장비 9대 × 지표 26개 = 매시간 234개의 숫자가 쌓여서, 사람이 모두 보고 이상을 알아채기 어렵습니다.
- 이상을 발견해도 "왜 그런지"를 판단하려면 관련 지표, 다른 장비 상태, 점검 절차를 일일이 찾아봐야 합니다.

CoreWatch는 이 두 단계를 돕습니다.

1. **이상 탐지:** 머신러닝 모델이 장비·지표별로 "이 시간대의 평소 모습"과 비교해 이상을 찾고 알람을 만듭니다.
2. **원인 분석:** 운영자가 알람을 고르면, 에이전트가 근거 자료를 직접 조회해 분석 리포트를 작성합니다.

## 리포트 구성

리포트는 확인된 사실과 AI의 추정을 섞지 않도록 세 부분으로 나눕니다.

| 구분 | 내용 |
|---|---|
| 조회한 사실 | 알람이 난 지표의 실제 값과 평소 값, 같은 절차의 다른 지표, 같은 시각 다른 장비의 상태 |
| 점검 절차 | 해당 지표와 관련된 점검 절차 문서의 내용과 출처 |
| AI의 원인 추정 | 가능한 원인과 각 원인의 근거, 점검 순서. 근거가 부족하면 "원인을 특정할 수 없음"이라고 답함 |

## 사용 기술

| 기술 | 이 프로젝트에서 하는 일 |
|---|---|
| 머신러닝 이상 탐지 (Isolation Forest) | 네 가지 단서를 종합해 이상 점수를 계산: 평소 같은 시간대와의 차이, 1시간 전과의 차이, 같은 시각 다른 장비와의 차이, 같은 절차의 짝 지표(시도 건수 ↔ 성공률)와의 관계 |
| MCP (Model Context Protocol) | AI가 부를 수 있는 도구 제공: 지표 조회, 이상 점수 조회, 알람 목록, 주변 상황 조회 |
| 멀티 에이전트 (LangGraph) | 조사를 지표 분석 · 장비 비교 · 절차 검색 담당 에이전트로 나누고, 총괄 에이전트가 필요한 것만 호출 *(구현 중)* |
| RAG (검색 증강 생성) | 점검 절차 문서 중 알람 내용과 뜻이 가까운 문서를 찾아 리포트 근거로 사용 *(구현 중)* |
| 실시간 진행 표시 (SSE) | 분석이 어느 단계까지 진행됐는지 화면에 바로바로 표시 |
| 실행 기록 (LangSmith) | 요청 하나가 어떤 단계와 도구를 거쳤는지, 단계별 시간과 사용량을 기록 |

## 폴더 구조

```
mme/                데이터 읽기(data.py), 이상 탐지 모델(detect.py)
mcp_server.py       AI가 부르는 도구 모음
agent/              에이전트 흐름 (질문 분류 → 계획 → 조사 → 작성 → 검사)
eval/               이상 탐지 모델 평가
tests/              도구를 하나씩 직접 실행해 보는 확인용 스크립트
server.py           백엔드 서버 (포트 8100)
web_chat.html       웹 화면 (web_demo_server.py로 실행, 포트 8600)
doc/                에이전트 기본 구조 설명서
sh/                 설치·실행 스크립트
```

## 실행 방법

Python 3.11 이상이 필요합니다.

```bash
# 1) 설치 (처음 한 번)
bash sh/setup_venv.sh
cp .env.example .env

# 2) 도구 확인
DATA_MODE=original .venv/bin/python3 tests/try_kpi_tool.py
DATA_MODE=original .venv/bin/python3 tests/try_detect_tool.py

# 3) 이상 탐지 모델 평가
DATA_MODE=original .venv/bin/python3 eval/eval_detector.py

# 4) 에이전트와 웹 화면 실행
bash sh/run_agent_ollma.sh      # 로컬 AI 모델(Ollama)로 실행
bash sh/run_frontend.sh         # 브라우저에서 http://localhost:8600
```

`DATA_MODE`로 사용할 데이터를 고릅니다.

| 값 | 데이터 | 사용 범위 |
|---|---|---|
| `original` | 제공받은 실제 장비 데이터 (엑셀) | 내 컴퓨터 안에서, 로컬 AI 모델로만 사용 |
| `synthetic` (기본값) | 실제 데이터와 무관하게 새로 만든 가짜 데이터 | 외부 AI 서비스, 실행 기록 서비스, 공개 시연 |

## 데이터 사용 원칙

- 실제 장비 데이터 파일(`*.xlsx`, `*.p`)은 저장소에 올리지 않습니다. 저장소 바깥의 `../Data/` 폴더에 두고 사용합니다.
- 실제 데이터로 실행할 때는 외부 AI 서비스와 실행 기록 서비스를 쓰지 않습니다.
- 데이터에 들어 있는 정답 표시(이상 여부)는 모델을 평가할 때만 읽습니다. 에이전트는 정답을 보지 않고 판단합니다.

## 이상 탐지 모델 평가 결과

7일치 시간별 데이터를 시간 순서대로 나눠 앞의 3일로 학습하고, 다음 1일로 모델을 고른 뒤,
마지막 3일로 한 번만 평가했습니다. 세 방법 모두 학습 기간에 알람이 같은 비율(0.3%)만큼 울리도록 맞춘 뒤 비교했습니다.

| 방법 | 설명 | 평가 기간 이상 29건 중 찾은 수 | 잘못 울린 알람 |
|---|---|---|---|
| 고정 기준 | 하루 종일 같은 정상 범위로 판단 | 10건 | 22건 |
| 시간대별 평소값 | 시간대마다 다른 정상 범위로 판단 | 17건 | 41건 |
| **머신러닝 (Isolation Forest)** | 네 가지 단서를 종합해 판단 | **20건** | 66건 |

머신러닝 모델이 가장 많은 이상을 찾았지만, 그만큼 잘못 울린 알람도 많았습니다.
놓친 9건 중 6건은 하루 패턴이 일정하지 않은 지표에서 나왔습니다.
